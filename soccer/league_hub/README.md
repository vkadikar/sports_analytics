# The Gentlemen's Invitational — League Hub

Web hub for The Gentlemen's Invitational Fantasy Premier League (2026–27): league table, matches,
Champions League and Lingineni Cup, manager profiles, league history, and rules.

## How it works

| File | Role |
|---|---|
| `index.html`, `style.css`, `app.js` | The site. Everything is rendered in the browser from `data.js`. |
| `data.js` | The league dataset. Generated by `sync_data.py`; never edit it by hand. |
| `sync_data.py` | Pulls live data from Fantrax (plus Premier League kickoff times) and writes `data.js`. |
| `app.py` | Flask server. Serves the site and re-syncs `data.js` from Fantrax when it's stale. |
| `news.py`, `news/` | Commish Bot's weekly recaps and previews, written once and cached as markdown (see "News"). |

### Gameweek timing

Each gameweek has two moments, both in US Eastern time:

1. **Official end: 8 hours after its last real Premier League match kicks off.** GW 7's last match kicked
   off Mon Oct 19 at 3:00 PM, so GW 7 officially ended at 11:00 PM that night.
2. **Home page switch: the first 9:00 AM after the official end.** For GW 7, Tue Oct 20 at 9:00 AM. Until
   then the home page keeps showing GW 7's results. An open tab reloads itself at the switch.

While a gameweek is live (from its start until the official end), the site shows the latest data:

| | While live | At the official end |
|---|---|---|
| Match scores | Live, labelled **Live** | Final |
| Table: points, W-D-L, form | Unchanged | Updated |
| Table: points for/against, +/- | Include live scores; clubs level on points re-sort by them | Final |
| Weekly high score | Current leader, "leading the race for $10" | "won $10" |
| Efficiency, optimal/median tables, head-to-head, Champions League table, all-time records | Unchanged | Updated |

Between the switch and the next gameweek's first scores, the high-score tile keeps showing the last winner.

- Kickoff times come from the public Fantasy Premier League API
  (`fantasy.premierleague.com/api/fixtures/`), matched to each Fantrax gameweek by date, so postponed
  matches are handled automatically. If that API is unreachable, a gameweek officially ends at midnight
  ET after the last day of its Fantrax scoring period.
- The 8-hour delay is `GAMEWEEK_END_AFTER_LAST_KICKOFF` and the 9 AM switch is `SWITCH_TIME`, both in `sync_data.py`.

### Data freshness

When a browser loads the site, the server re-runs the Fantrax sync before serving `data.js` if either:

- the last sync is older than `DATA_SYNC_TTL_MINUTES` (default 15), or
- a gameweek has started or officially ended since the last sync.

If Fantrax is down, the last good `data.js` is served. The footer shows when the data was last updated.

### Lineups and squads

Clicking any matchup (match cards, home-page results, Champions League fixtures, or a manager's fixture
list) opens both teams' starting XIs and benches with each player's points for that gameweek. A manager's
profile lists their current squad with season points. These load from Fantrax through the server on demand:

| Endpoint | Returns | Cached for |
|---|---|---|
| `/api/lineups/<gw>?teams=<id>,<id>` | Starters, bench and injured reserve for each team that gameweek | 24h once the gameweek is official, 2 min while live or upcoming |
| `/api/squad/<team id>` | Current players with season-to-date points | 10 min |

Starters' points are what counted toward the matchup (each player scored in the slot they filled), so they
add up to the team's score. Bench points are what those players scored at their own position. Team ids are
the `teamId` on each manager in `data.js`. On a static host without `app.py`, these sections show a message
instead.

### News (Commish Bot recaps and previews)

The **News** tab carries Commish Bot's write-ups, and the home page shows the latest recap next to the
preview of the following gameweek:

| Post | Written | File |
|---|---|---|
| Recap of gameweek N | Once gameweek N officially ends | `news/gw08-recap.md` for GW 8 |
| Preview of gameweek N+1 | At the same time, if N+1 hasn't kicked off yet | `news/gw09-preview.md` for GW 9 |

Posts are written once and committed; the site serves them from `/api/news` and never regenerates them.
`news.py` syncs from Fantrax, then has Commish Bot (the `gameweek_recap` and `gameweek_preview` skills in
`soccer/llm_client/skills/`) write any post that's missing. A recap only uses data up to its own gameweek,
so backfilled recaps read as if written that week.

**Automation.** The GitHub Action `.github/workflows/league-news.yml` runs `news.py` every morning at
12:30 UTC, before the home page's 9 AM ET switch, and commits new posts (plus the fresh `data.js`) to
`master`, which redeploys Render. Most mornings there's nothing to write and it exits after the sync. It
needs two repository secrets (**Settings → Secrets and variables → Actions**):

| Secret | Value |
|---|---|
| `FANTRAX_COOKIE_B64` | Same value as on Render (see "Deploying to Render" below) |
| `GEMINI_API_KEY` | Same key as Commish Bot uses |

Run it by hand from the **Actions** tab (**League news → Run workflow**), or locally from the repo root:

```bash
python3 soccer/league_hub/news.py --dry-run            # list what's missing
python3 soccer/league_hub/news.py                      # write it
python3 soccer/league_hub/news.py --recap 5 --force    # rewrite one post
```

To fix a post by hand, edit its markdown file and commit it; the title is in the frontmatter.

### All-time records

The all-time table and each manager's career record are running totals: their record through 2025–26
(`ALL_TIME_BASELINE` and `MANAGER_HISTORICAL_PROFILES` in `sync_data.py`) plus every final gameweek
this season. Relegated managers' records stay frozen. The table is ranked by points per week.

**At the end of each season**, fold that season's records into those baselines so they aren't counted twice
when the next season's data starts.

## Running locally

```bash
python3 -m venv .venv && source .venv/bin/activate     # from the repo root
pip install -r soccer/league_hub/requirements.txt
python3 soccer/league_hub/app.py                        # http://localhost:8080
```

The server reads the Fantrax login cookie from `fantraxloggedin.cookie` at the repo root.

To refresh `data.js` without running the server: `python3 soccer/league_hub/sync_data.py`

## Deploying to Render

The app runs as a Render **Web Service** from the repo root. You can create it from the dashboard, or let
Render read the `render.yaml` blueprint at the repo root (**New → Blueprint**) and then fill in the secret.

### 1. Encode your Fantrax cookie

The server logs in to Fantrax with your browser cookie file. It's binary, so it's passed to Render as a
base64 string. On your Mac, from the repo root:

```bash
base64 -i fantraxloggedin.cookie | pbcopy
```

This copies a single line (about 2,000 characters) to your clipboard. Treat it like a password: anyone
with it can act as you on Fantrax.

### 2. Create the Web Service

In the Render dashboard: **New → Web Service**, connect the repository, then set:

| Setting | Value |
|---|---|
| Language / Runtime | `Python 3` |
| Branch | `master` |
| Root Directory | *(leave empty: the repo root)* |
| Build Command | `pip install -r soccer/league_hub/requirements.txt` |
| Start Command | `gunicorn --chdir soccer/league_hub app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120` |
| Instance Type | `Free` works; any paid instance avoids cold starts (see below) |
| Health Check Path | `/api/health` (under **Advanced**) |

Keep `--workers 1`: each worker process syncs on its own, so more workers mean more Fantrax calls for no benefit.
Threads handle concurrent visitors.

### 3. Environment variables

Under **Environment**, add:

| Key | Value | Required |
|---|---|---|
| `FANTRAX_COOKIE_B64` | The base64 string from step 1 | **Yes** |
| `FANTRAX_LEAGUE_ID` | `iku2an1nmryzcfa2` | Optional (this is the default) |
| `DATA_SYNC_TTL_MINUTES` | `15` | Optional. Minutes between Fantrax syncs while people are visiting. |
| `PYTHON_VERSION` | Your local version, e.g. `3.14.3` (`python3 --version`) | Recommended, so Render matches what you tested |

Don't set `PORT`; Render provides it.

### 4. Deploy and check

Click **Create Web Service**. When the deploy finishes:

1. Open `https://<your-service>.onrender.com/api/health`. It should show `"fantrax_sdk_loaded": true` and `"cookie_present": true`.
2. Open the site. The footer's "Updated …" time should be within the last few minutes.
3. In the service's **Logs**, a sync shows as `Connecting to Fantrax API…` followed by `Completed GWs: [...]`.

### Things to know on Render

- **Free instances sleep** after 15 minutes without traffic. The next visit wakes the server, which can take
  up to a minute, and that first page load runs a fresh sync.
- **The disk resets** on every deploy and restart, so `data.js` goes back to the committed copy until the
  first sync. Commit a freshly synced `data.js` occasionally so the fallback is never far behind.
- **When the Fantrax cookie expires**, syncs fail (the logs show `Warning: data sync failed`) and the site keeps
  showing its last data. Log in to Fantrax again locally to refresh `fantraxloggedin.cookie`, repeat step 1,
  and paste the new value into `FANTRAX_COOKIE_B64`. Saving an environment variable redeploys the service.
- **Keep the cookie out of git.** With `FANTRAX_COOKIE_B64` set, the repo doesn't need the cookie file, and
  `.gitignore` already excludes `*.cookie` and `.env` files. Check nothing slipped in with
  `git ls-files | grep -E "cookie|\.env"` (it should print nothing). Copies pushed before they were ignored
  are still in git history, so if the repo has ever been public, log out of Fantrax everywhere to invalidate
  the old cookie.
